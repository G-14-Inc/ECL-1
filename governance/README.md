# ECL-1 governance papers

ECL-1 is maintained by G-14, Inc. and developed in the open by the ECL-1
Working Group. These papers say how the working group works and decides, how
ECL-1 changes, is reviewed in public and released, how conformance is claimed,
and how errata, security reports and appeals are handled. They create no
standards body, certification authority or legal entity.

| Paper | Purpose |
| --- | --- |
| `CHARTER.md` | The charter of the ECL-1 Working Group: scope, taking part, roles, how decisions are made, working sessions, public review, interests, intellectual property and changing the charter |
| `CONTRIBUTING.md` | How to contribute: Developer Certificate of Origin sign-off on every commit, inbound terms equal to outbound terms, the patent pledge for contributions, no contributor license agreement; `DCO.txt` is the certificate |
| `PUBLIC_REVIEW.md` | The public review of each new minor or major version: 30 or 60 days, comments as GitHub issues, a published disposition for every comment; `review-disposition-log-template.json` starts a disposition log |
| `CONFORMANCE_CLAIMS.md` | How an implementer claims conformance and is listed, as self-declared, in the implementers registry |
| `CHANGE_CONTROL.md` | Change classes, discussion periods, compatibility, review and decisions |
| `RELEASE_POLICY.md` | Versions, release states, freeze, checks, signing, publication and withdrawal |
| `ERRATA.md` | The errata procedure: reporting, classification, review and publication |
| `ERRATA_AND_DISCLOSURE.md` | Defect classes, erratum records and defect disclosure |
| `REGISTRY_POLICY.md` | Durable allocations, namespaces, collisions and emergencies |
| `SECURITY.md` | Security intake, triage, remediation and coordinated disclosure |
| `APPEALS.md` | Appeals: to the chair, then to a public issue |
| `CODE_OF_CONDUCT.md` | The participation code and its enforcement |
| `ASSESSOR_INDEPENDENCE.md` | Assessor competence, conflicts, separation and prohibited claims |
| `TRADEMARKS_AND_MARKS.md` | Descriptive use of the name, conformance claims and the absence of any certification mark |

How to join the working group, its sessions and the public repository's kit
are in `community/`. The licenses and the patent pledge are in
`../LICENSING.md` and `../PATENTS.md`.

## Fail-closed rule

If a required role, contact, reviewer, legal decision, assessor, signing key,
or authorization of the maintainer is absent, the affected action is not
authorized. Silence, repository access, tool output, or authorship does not
substitute for the missing authority.
