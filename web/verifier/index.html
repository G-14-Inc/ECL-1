Verify ECL-1 evidence

This page checks an ECL-1 evidence bundle, or an offline package that carries one, against a trust policy that you supply. It verifies each signature, the bindings between requests, decisions and events, whether the record of each action is complete, whether each decision's record of its inputs shows that only verifiable inputs supported it, and whether each release records a discharge of the obligations that its decision left to enforcement before the release. For an offline package it first checks the archive and its manifest, and it treats the trust policy, keys and snapshots inside the package as evidence: only the trust policy you supply decides. It runs the TypeScript library of the ECL-1 command-line verifier, ecl-verify-ts, and reaches the same verdicts as that command on the shared conformance vectors.

Your files stay on this device. The page reads them in the browser and makes no network request: its content security policy forbids every connection.

The records of a bundle make different claims: the authorization in a decision says what an action may do and under which conditions, the enforcement point's events say what it checked and released, and the record of the outcome, or an observer's record, says what happened. A verified bundle shows which keys signed which statements, and that the statements are consistent with each other and complete. It does not show that the statements are true, such as that the enforcement point checked and released as its events record or that the effects happened, and it is not a certification. Each result lists, with its verdict, what the verdict does not establish, such as that the recorded times are the true times of the events or that the obligations a decision left to enforcement were met, and then the checks that held.

Files

An evidence bundle, a JSON file of at most 1 MiB, or an offline package, a ZIP file of at most 16 MiB.

The keys you trust, what each key may sign, and which keys are revoked. A JSON file of at most 256 KiB.

Each object names the trust-policy version in force when it was signed. If that is not the version above, add the version it names here. You can choose several files.

The register under which the decisions were made. Each decision basis must then name this version of the register and list exactly the decision inputs that it declares for the action, with the declared class. A JSON file of at most 1 MiB.

Evaluation

Use the instant at which you verify, written like 2026-10-01T00:00:00Z. Each signing key's current status is checked then, and evidence dated later is invalid. Version 1.0 offers no as-of assessment. Leave it empty to use the current time.

Every signature of every envelope and observation must be covered by a valid countersignature from a time authority in your trust policy. Each covered signature is judged at its attested time.

Choose this only after deciding to rely on evidence signed by a key that your trust policy no longer accepts. A result whose only failure is current trust then says verified and states that you accepted the failure. Invalid and incomplete results stay unchanged.
